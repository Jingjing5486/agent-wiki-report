# v0.1 评估范围

当前代码做结构校验和运行统计，尚未实现语义评分。`structural_pass=true` 不等于事实正确，也不是生产准入结论。

## 自动检查

- 资料快照哈希及证据与提取文本的字符位置匹配。
- 非空页面、章节、主张及类型。
- 页面标识合法、唯一，不覆盖索引或越界写文件。
- 每条主张有引用，且 evidence_id 存在。
- 完全重复文本提示；未引用证据清单。
- 模型返回异常、截断、空内容和无效 JSON。

引用来源数、证据片段数只用于观察材料使用情况，不代表关键知识覆盖率。结构校验允许“引用存在但内容不支持”的错误通过，测试特意覆盖此限制。

## 人工核验

生成后填写 `review.csv`：每条主张标注 supported 为 yes/no/partial/uncertain，并写理由。

另外从原始资料独立列出关键知识点，检查候选是否正确覆盖，而不是让候选自己定义覆盖标准。整套 Wiki 还需评价跨资料综合、重复、分歧表达及页面边界。

建议第一轮盲评：固定语料与模型配置，分别运行 baseline 和 synthesis Prompt，隐藏方案名后审阅。模型输出预算相同，提示词长度不同会带来少量输入 token 差异，应记录而不是忽略。

`compare` 展示基础统计，不自动选出赢家。离线 extractive 模式不执行 Prompt，不适合用于 Prompt 效果实验。
